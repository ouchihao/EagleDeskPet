# v1.10.1 · 猜拳动作修订

## 这次修的是什么

旧版猜拳每段只有 5 个关键姿势（含两端站立），峰值手势几乎没有停留。内部姿势跨度过大，输后捂脸尤其容易出现手部重影；虽然最终有 121 张 PNG，并不代表有足够的原画设计。

此次用原生 ImageGen 重绘默认、上班装、卫衣三套形象的石头、布、剪刀、得意、捂脸，共 15 张 4×4 原画表。各段采用 16 个关键位置，首尾引用对应服装的原始站立图；平局继续使用原有害羞，不重做哈欠或其他日常动作。

| 动作 | 新时长 / 输出 | 表演设计 |
| --- | --- | --- |
| 石头、布、剪刀 | 2.8 秒 / 169 张 PNG | 抬肘、转腕、手指逐渐成形；第 60–112 帧保持清晰拳型约 0.87 秒，再收拢、落手 |
| 得意 | 2.4 秒 / 145 张 PNG | 双手渐抬、表情变化、放松并落手；不跳跃或整体翻转 |
| 捂脸 | 2.4 秒 / 145 张 PNG | 同一侧手沿脸侧抬起、遮眼、沿脸侧放下；不突然换手 |

展示段是四个稍有变化的姿势之间的微动，不是复制一张 PNG 假装增加帧数。含 0.6 秒准备，输赢一轮演出最少 5.8 秒，平局 5.4 秒；预载和前一动作收尾时间另计。取消仍等当前动作完整落回站立，不提前发奖励。

## 不只是加图片

第一次新图回放仍发现三类问题，并据此调整构建流程：

- 站立接缝过短：原候选末段只有 6 个采样间隔，新旧原画的五官比例恢复显得急。最终给出拳两端各 20 个间隔，手指展开仍保留每小步 8 个间隔，不把中段挤成仓促的出拳。
- 锁帧坐标不一致：对插值图做根位置校正后，又把关键位置强制换回未移动的原图，会产生约半像素的瞬时回跳；透明边缘收紧还可能被脚底检测误认为整体上移。新版猜拳使用逐段关键位置校准，校正量在原画位置为零，继续保留原画像素锁定和原有质量阈值，不以淡入淡出掩盖。
- 半透明边缘污染：插值和去底对“不透明像素”的判定不同，少数边缘会残留亮色。新增仅用于该校准流程的外边缘 RGB 修复，从附近真正不透明的角色像素取色；不改透明度、形状、内部颜色或锁定原画，仍用原有深色背景阈值验收。

逐帧检查既看手部遮挡和节奏，也看深浅背景边缘与首尾形体。像素差分只用于定位，不把平均差分小、PNG 数量多或单个测试通过当作“绝对丝滑”的证明。画面仍是同一角色的不同绘制姿势，不宣称所有五官像素完全不变。

## 原画与重建

- 原画和完整提示词：[`RpsV2/PROMPTS.md`](../DuckDeskPet/Assets/AnimationSources/RpsV2/PROMPTS.md)。有错误背景或换手的生成结果不纳入运行资源。
- 分段时序：[`rps_animation_timing.py`](../tools/rps_animation_timing.py)。
- 构建：[`prepare_rps_animation.py`](../tools/prepare_rps_animation.py)，只写仓库 `.codex-build` 中明确命名的临时目录。
- 安装经过验证的素材：同一命令加 `--promote`，所选动作全量验证完成后才写生产目录，保留旧文件备份；缺帧、失败报告、过期原画或顺序映射会拒绝替换。
- 原帧回放：[`inspect_rps_playback.py`](../tools/inspect_rps_playback.py)，支持 staging 快照、原速 / 慢放 / 逐帧、透明 / 深 / 浅底和同服装哈欠对照。页面没有 CSS 转场或额外补帧。

```powershell
python tools/prepare_rps_animation.py --output-root .codex-build/rps-review --keys-only
python tools/prepare_rps_animation.py --output-root .codex-build/rps-review --rife <rife-ncnn-vulkan.exe> --rife-model <rife-v4目录>
python tools/inspect_rps_playback.py --snapshot .codex-build/rps-review-playback --capture --staging .codex-build/rps-review
# 回放与报告均检查后：
python tools/prepare_rps_animation.py --output-root .codex-build/rps-review --promote
```

旧的扩展 / 整套服装构建脚本不再使用五关键姿势重建猜拳。RIFE 仅是离线制图依赖，运行 EXE 不需要安装它；使用不透明 RGB 底图和独立透明度图，不能直接把 RGBA 喂给旧版 RIFE。

### 已知细微残差

本次消除了明显换姿势突变及锁帧引起的单帧整身回跳，但不宣称每帧零形变：

- 默认“布”第 103→104 帧仍有约 1.25 个源图像素的微小横向量化偏移，维持约两帧后缓慢回归，不是旧的单帧反向回弹。
- 卫衣得意动作约第 42–46、93–97 帧，捂脸约第 34–36 帧，袖口旋转有短暂柔化。角色、手、衣袖的遮挡关系保持，未见手脱体或明显穿透。

以上作为可继续打磨的插帧限制保留记录，不能以 QA 数值通过替代视觉评价。
