## 去掉饱食度

- 不再存储或显示饱食度，不因饥饿拒绝开工或自动收工；开始工作后可以一直工作，直到主动取消
- 一份饭消耗 1 份粮食、增加 20 心情，上限 100，不再额外增加经验；仍记录有效餐数和原有成就
- 心情满时不扣粮；缺粮、2 秒冷却、动作队列拒绝也不扣粮；一份饭仍对应一次完整吃饭动画
- 粮袋规则保留：初始 5 份，每挂机 5 分钟 +1，上限 99；摸头仍 +3 心情，10 秒奖励冷却
- 工作心情每小时下降 10，休息每小时下降 1，装备最多减免 50%；降到 0 只降低工资，不停工
- 原 T-T 空碗表演作为手动“馋饭小剧场”保留，不再由饱食度自动触发；低心情的自主反应仍受开关、冷却与工作状态约束

工作中仍先收工再吃饭 / 摸头，完整交接后才能播放互动；本次不顺带改变这套动作调度。暂停动画不是停止工作的代称，取消工作才结束工作收益。

## 工资如何计算

`每分钟鹰币 = 1.00 × (0.50 + 心情 / 200) × (1 + 生效装备金币加成)`

| 当前心情 | 心情效率 | 默认装备工资 / 分钟 |
| ---: | ---: | ---: |
| 0 | 50% | 0.50 |
| 50 | 75% | 0.75 |
| 70（新档） | 85% | 0.85 |
| 100 | 100% | 1.00 |

工资按整个时间区间内实际下降的心情积分，不拿结束时的低心情倒算整个区间，也不按每次调用舍入零钱。余额保留两位小数，未满一分的部分持久化。装备只在实际显示生效后才计算，预览、待生效或缺失资源不提供属性；同槽替换不叠加旧物。

三槽装备金币属性相加，上限 +250%；经验属性相加，上限 +200%；心情衰减减免上限 50%。原“饱食衰减减免”属性移除，不悄悄转换成额外金币加成。工作经验仍为基础 1 XP / 分钟 × 装备经验倍率，不受心情影响。当前最强三件组合实际为金币 +200%、经验 +160%、心情减免 50%。

在线持续工作没有七小时饥饿上限；**离线、休眠或长时间进程挂起仍最多补算两小时**，不是关闭程序七天就能领取七天工资。原 UTC 高水位、有效工作游标、防重复结算和钱包 999,999.00 上限保留。开始收工后不继续发工资。

## 七天的计算口径

新档 70 心情、0 鹰币、默认装备，从开始工作起不喂饭、不摸头、不购买或装备任何奖励，程序保持运行：前 7 小时心情从 70 降到 0，此后工资为每分钟 0.50。

- 7 天的保底工资：`7 × 24 × 60 × 0.50 = 5,040.00`
- 前 7 小时的心情额外工资：`420 × (0.35 + 0) / 2 = 73.50`
- 连续 7 天合计 **5,113.50**，最低商品 **5,100.00**，约第 **6 天 23 小时 33 分钟**攒够

这是无人照料、无加成的基准，不是所有玩法都强制等待七天。维持高心情可更快，已购装备 / 免费奖励也会提高速度；原已购商品保留，因此老玩家清零后可能更快。喝茶和薄荷桌的原免费成就途径保留，免费解锁不等于鹰币购买；无需为了养宠被迫买商品。

## 新版一次性金币重置

存档版本升为 v4。首次从 v1 / v2 / v3 升级时，金币与未结工资余数清零，旧累计工时或旧离线区间不能把清掉的钱补回来。下一次保存 / 重启使用 v4，不再清零新赚的钱。

迁移前保存原文件的独立备份，文件名为 `pet-state.pre-v4-<原文件SHA256>.json`，位于同一数据目录，不能被普通的滚动 `.bak` 覆盖；备份或迁移保存失败时不覆盖旧存档，也不允许据此确认交易。原版本存档恢复到旧版需使用迁移前备份，不能用旧程序写回 v4。

保留已购商品、装备、荣誉、餐数、粮食与等级进度；v3 的 XP 原样保留，v1 / v2 仍沿用既有的旧经验曲线换算以保住等级与级内比例。旧交易收据保留，防止同一购买重复扣款。不删除用户整个数据目录，不清除便签、提醒、GitHub 或 AI 配置。

这条原有图形初始化路径没有被心情规则改动，但必须在发布前单独验证失败处理。微软的[控件 API 说明](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.wpf.webview2compositioncontrol?view=webview2-dotnet-1.0.4191.47)列出了异步初始化、模板与释放接口；本机锁定 SDK 的 `Loaded` 图形初始化不属于 `EnsureCoreWebView2Async` 的普通等待异常路径。
